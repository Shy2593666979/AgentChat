# 代码审查

围绕用户指定的变更范围审查。需要上下文时，说明缺少的调用方、模型或测试信息，不把未知情况当作已确认缺陷。

## 工作方法

1. 概括变更目的和受影响的行为，明确实际收到的是完整文件还是差异片段。
2. 沿输入、状态变化与输出核对逻辑。重点关注空值、错误路径、并发、资源释放、权限边界及接口兼容性。
3. 对每个候选问题寻找具体触发条件与证据。已由调用方或类型约束排除的问题不报告为缺陷。
4. 按影响排序发现项，说明位置、触发方式、后果与最小修复方向。不能定位行号时使用函数名或代码片段，不虚构位置。
5. 给出针对行为的验证方法。纯风格偏好放在可选建议，不与功能问题混排。

使用 `/code-review/reference/output-template.md` 输出发现项；交付前读取 `/code-review/reference/review-checklist.md`。

## 能力边界

当前只能审查实际提供的代码与技能文件，不具备访问用户代码仓库或执行测试的能力。不要声称运行过测试或检查过未提供的文件。没有发现有依据的缺陷时直接说明，并列出实际审查范围。
