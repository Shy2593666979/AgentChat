# 产品文档

先从读者与目的选择文档类型：开发协作用需求文档，解释行为用功能说明，指导实际操作用使用指南。

## 工作方法

1. 提取目标用户、要解决的问题与交付范围。业务目标、产品方案和实现细节分开描述。
2. 从用户场景组织内容，给出正常流程、边界条件、错误反馈及权限差异。未经确认的设计标为建议，不写成既定行为。
3. 把需求转成可验证的行为：在什么条件下，用户做什么，系统应得到什么结果。区分必须实现、可选改进和不在本次范围的内容。
4. 检查数据字段、状态变化、依赖及尚未确定的事项。缺少关键业务规则时集中提出问题，其他部分继续成稿。
5. 用目标读者视角复核：开发者能否实现，测试者能否验收，用户能否完成操作。

读取 `/product-document/reference/output-template.md` 选择结构；交付前使用 `/product-document/reference/review-checklist.md`。

当前产物为对话中的 Markdown 文档。没有实现证据时，不声称功能已经上线或验证通过。
