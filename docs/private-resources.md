# 用户私有的默认资源

工具、Skill、MCP 服务和智能体均属于各自用户。系统用户 `0` 下的记录只作为初始化模板，不再拼接到个人列表，也不允许普通资源接口编辑其他用户或模板的记录。管理员在这些个人资源接口中同样只能访问自己的资源。

注册账号或通过用户服务创建账号时，在同一个数据库事务中复制默认资源：每条记录拥有独立 ID、所属用户和深拷贝的配置。智能体绑定的工具、Skill、MCP ID 同步指向该用户的副本。初始化读取本地模板，不调用模型或远程 MCP，也不重新生成已有元数据。

资源仍存放在现有四张表，不需要额外的初始化标记。`database/dao/user_resources.py` 中的 `UserResourcesDao.create_defaults()` 仅由 `UserDao._save_new_user()` 在创建账号时调用，使用独立 UUID，并与账号创建共用事务；任意一步失败时整体回滚。

系统启动由 `database/init_data.py` 创建表并加载系统模板，不扫描已有用户或迁移历史引用。字段与索引统一在 `database/models/` 中定义，首次建表时生成，不执行旧库结构迁移。

初始化固定按建表、模型、工具、Skill、MCP、智能体的顺序执行，不再通过智能体总数判断首次启动。重复执行只补齐缺失模板，系统模型连接参数按配置同步；个人副本不受影响。初始化不下载头像、连接远端 MCP 或调用模型生成名称，失败时记录异常并阻止服务启动，避免缺少模板的账号注册。

启动不会覆盖个人修改，也不会补回用户已删除的默认资源。以后新增模板不会自动下发给已创建用户。

列表、搜索、名称匹配只返回当前用户的资源。编辑、删除、智能体绑定和对话执行均校验归属，工作区使用 MCP 和插件时也校验；MCP 用户配置的按 ID 读取和删除额外校验配置所属用户。

模型和知识库不属于本次默认资源复制范围。模型列表沿用既有规则。

MCP 管理和注册聊天接口始终校验真实登录身份，忽略这些接口的免登录白名单配置。公开 MCP 协议入口 `/mcp/*` 保持原规则。会话列表按当前用户筛选，发送、确认、拒绝及删除均检查会话归属。

验证：`tests/test_private_resources.py` 覆盖独立 ID、配置深拷贝、绑定重映射及注册失败回滚。`tests/test_simple_config.py` 的临时数据库 HTTP 检查覆盖全新启动、双账号资源与会话隔离、越权拦截及重启，不修改真实用户数据。
